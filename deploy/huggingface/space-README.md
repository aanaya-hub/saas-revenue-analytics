# Northwind Analytics — B2B SaaS revenue dashboard

An interactive dashboard over a **synthetic** B2B subscription business: 200 customers, 4 months,
six related tables, and eight data defects injected on purpose so the cleaning step has real work
to do.

**The full project — generation code, analysis, SQL, tests and README — is on GitHub:**
[github.com/aanaya-hub/saas-revenue-analytics](https://github.com/aanaya-hub/saas-revenue-analytics)

## What you are looking at

This Space runs only the presentation layer. It installs two libraries (`dash`, `plotly`), reads one
precomputed JSON file, and draws five tabs:

| Tab | Question it answers |
| --- | --- |
| **Executive** | What happened to revenue, and how much of it is at risk? |
| **Revenue** | Where did the decline come from — new business, expansion, or churn? |
| **Churn risk** | Who is likely to leave, and what does intervening actually save? |
| **Segments** | Do the customer groups the business assumes actually exist in the data? |
| **Data & models** | What was wrong with the raw data, and how good are the models really? |

The analysis behind it runs in `analysis.py` on a normal machine, not in this container. That is a
deliberate choice: the full analysis stack (scikit-learn, XGBoost, HDBSCAN) is about 1 GB, so
baking it into a web image would make the Space slow to build and slow to start, for no benefit.

## Three results worth the click

- **MRR fell 25.6 %**, from $1,148,753 to $854,944, with $4,247,267 accumulated over the period.
- **A churn classifier reached 0.962 ROC-AUC** against a 0.500 majority baseline — and moving the
  decision threshold from 0.50 to 0.20 changes the value of the intervention from $65,200 to
  $11,500, a **$53,700 difference** at the same model.
- **The segments the business assumes are not in the data.** Clustering found no density structure
  (HDBSCAN returned 100 % noise; DBSCAN found one cluster), even though the same labels reproduced
  almost perfectly run to run (ARI 0.870).

## The caveats, stated up front

These matter more than the headline numbers, which is why they are here and not buried.

1. **The data is synthetic.** It was generated by a logistic process using the same features the
   churn model is then shown. So the 0.962 AUC is partly the model recovering the process that
   wrote the data. It demonstrates method, not real-world skill.
2. **The NPS model barely works.** R² is 0.252 and only 1 of 8 terms is statistically significant.
   It is reported as weak rather than dressed up.
3. **Three apparent findings are reported as artefacts** — segment churn differences, the discount
   effect, and the cluster structure. Each is explained in the **Data & models** tab.

The project README carries the full limitations section.
