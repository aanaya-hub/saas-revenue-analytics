# SaaS revenue analytics: synthetic B2B subscription data

A full analytics pipeline over a fictional B2B SaaS business. Generate the data, break it in eight documented ways, clean it, model it three ways, and deploy the result as a dashboard.

**Live demo:** [saas-revenue-analytics.onrender.com](https://saas-revenue-analytics.onrender.com)  
Free tier, so the first load takes about 15 seconds to wake. It is not broken.

**Stack:** Python · pandas · scikit-learn · statsmodels · XGBoost · Plotly · Dash · SQLite · Docker · pytest

Synthetic data, 200 customers over four months, no API keys and no paid services. Clones and runs offline.

---

## Three things the project found

**The default threshold was costing money.** The library default of 0.50 caught 68 percent of the customers who actually left. Rebuilt on what each kind of error costs, 0.20 caught 95 percent, worth about USD 53,700 on that book.

**The simplest model won.** Cross validated, a one feature linear model scored R squared 0.204 against Ridge at 0.139 and gradient boosting at 0.110. The complex models were worse.

**There are no natural segments.** A silhouette of 0.347, DBSCAN finding at most one cluster, and HDBSCAN labelling every customer as noise. The segmentation the business would want does not exist in this data.

---

## Three things it refuses to claim

**Three apparent findings are published as artefacts, not results.** Segment churn differences, the discount effect and the clusters each sit inside a confidence interval indistinguishable from noise.

**The revenue regression is an accounting identity.** MRR modeled from seats and price scores 0.936, which measures arithmetic rather than prediction. The honest target was sentiment, where one of eight terms is significant.

**The churn score is flattering.** A ROC AUC of 0.962 is high partly because the data was generated by a process using the same features the model sees. Read it as a check on the pipeline, not as a prediction about real customers.
